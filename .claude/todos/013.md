# #13 — Clarify profile workflow with examples

**Problem:** The profile system (init from profile, share on GitHub, export) is powerful but the flow is unclear. A new user wouldn't know how to: create a profile, share it, or consume someone else's profile.

**Current behavior:** Profile operations exist (`flowstate profile add/remove/status`) and `flowstate export` can generate shareable profiles. But there's no example profile in the repo and no end-to-end walkthrough.

**Expected behavior:**
1. Add 1-2 example profiles in `examples/profiles/` (e.g., `python-dev.json`, `rust-dev.json`)
2. Each example profile should be a valid, useful starting point
3. README or dedicated doc shows the full workflow:
   - "Export your config as a profile" → `flowstate export -o my-profile.json --name "My Profile" --description "..."`
   - "Share on GitHub" → push to a repo, reference as `github:user/repo`
   - "Init from a profile" → `flowstate profile add github:user/repo`
   - "Update when upstream changes" → `flowstate update`
4. The example profiles themselves serve as documentation of the format

**Edge cases:**
- Example profiles should not contain user-specific paths or internal domains
- Examples should pass schema validation
- Examples should work across tiers (or specify a recommendedTier)

**Test plan:**
- Schema validation test: example profiles pass `validate_profile()`
- Smoke test: `flowstate profile add local:examples/profiles/python-dev.json` works
- Manual: follow the documented workflow end-to-end

**Scope:**
- IN: Example profiles, workflow documentation, possibly CLI help text improvements
- OUT: No changes to profile system internals. No new commands.
