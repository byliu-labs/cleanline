# #14 — Evaluate combining tighten and clean commands

**Problem:** `tighten` (remove stale rules from config) and `clean` (consolidate redundant allow-list entries in settings.json) are separate commands but serve a complementary purpose: reducing bloat. Users might not know which to run or when.

**Current behavior:**
- `flowstate clean`: analyzes `settings.json` allow list, finds redundant entries covered by wildcards, proposes consolidations (grouping specific entries into wildcards). Operates on settings.json.
- `flowstate tighten`: analyzes `hook.jsonl` audit log for stale rules (aliases, mappings, domains, file paths not used within staleness window). Removes from lockfile user_config or suppresses profile rules. Operates on lockfile.

**Options to evaluate:**
1. **Merge into one command** (e.g., `flowstate optimize` or `flowstate tidy`): runs both analyses, presents combined report, applies both sets of changes with `--apply`
2. **Keep separate but add `flowstate maintain`** as an umbrella that runs both
3. **Keep separate** — they operate on different files (settings.json vs lockfile) and have different mental models

**Key considerations:**
- Different data sources: clean reads settings.json, tighten reads hook.jsonl + lockfile
- Different outputs: clean writes settings.json, tighten writes lockfile
- But from the user's perspective: "make my config leaner" is one intent
- Risk of combining: longer output, harder to understand what changed where
- `clean` is about the Claude Code allow list; `tighten` is about flow-state's own config

**What would resolve this:** Try prototyping the combined output. If it's clean and comprehensible under ~30 lines, merge. If it's noisy, keep separate.

**Impact if ignored:** Minor UX friction — users need to know about two commands instead of one. Not blocking.

**Scope:**
- IN: Evaluate UX, possibly merge commands or add umbrella command
- OUT: No changes to the underlying analysis logic in clean_cmd.py or tighten.py
