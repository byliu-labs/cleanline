# #12 — Improve setup command console output

**Problem:** `flowstate setup` prints summary counts but doesn't show the user *what* rules are being generated. Users can't verify correctness or understand what they're getting without reading the config file afterward.

**Current behavior:** Setup prints lines like "Found N canonicals, N aliases, N domains" — opaque.

**Expected behavior:** After the summary counts, show a representative sample:
- 3-5 example aliases (e.g., `python3.12 -> python`, `cargo-clippy -> cargo`)
- 3-5 example domains (e.g., `*.docs.rs`, `*.python.org`)
- 2-3 example file read paths (e.g., `~/.config/**`, `/tmp/**`)
- 2-3 example command mappings if any exist
- A "... and N more" line for each category if there are additional entries
- Keep total output under ~20 lines so it doesn't overwhelm

**Edge cases:**
- Zero entries in a category: skip that section entirely
- Very few entries (< sample size): show all, no "and N more"
- `--yes` mode: still show the sample (it's informational, not a prompt)
- `--dry-run`: sample is part of the dry-run preview

**Test plan:**
- Unit test: verify sample output contains expected entries for each tier
- Integration test: `run_setup()` with captured stdout shows sample lines
- Manual: run `flowstate setup --dry-run --tier balanced` and verify readable output

**Scope:**
- IN: Console output formatting in `setup_cmd.py` and/or `cli.py`
- OUT: No changes to config generation logic. No changes to what gets written.
