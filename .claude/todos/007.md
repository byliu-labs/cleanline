# #7 — flowstate clean: allow list consolidation

**Problem:** Users accumulate verbatim allow entries in `settings.json` over time. Once Flow State is installed, some entries become doubly redundant (covered by wildcard AND alias). The allow list grows monotonically and becomes unreadable.

**Current behavior:** No CLI command to analyze or clean `settings.json`. The `/clean-permissions` skill exists as a prompt-only local skill but is not part of Flow State.

**Expected behavior:** `flowstate clean` scans `~/.claude/settings.json` allow list and identifies three categories:
1. **Redundant entries** — covered by existing wildcards in the same list (e.g., `Bash(git -C /foo log)` when `Bash(git *)` exists). Removable.
2. **Flow State handled** — covered by alias/mapping resolution (e.g., `Bash(python3.12 *)` when alias exists). INFORMATIONAL ONLY, never removed (would create dependency on Flow State being installed).
3. **Proposed consolidations** — 3+ specific entries → narrowest wildcard (e.g., `docker compose up/down/build` → `Bash(docker compose *)`). Uses longest common prefix.

Interactive apply flow: show proposals → user confirms → atomic write to settings.json.
Status integration: `flowstate status` reports allow list health (day one, low cost).

**Edge cases:**
- settings.json missing or unreadable → graceful error
- Allow list empty → "Nothing to clean"
- Consolidation that only saves 1 entry → skip (min_group=3)
- Non-Bash entries (WebSearch, MCP tools, Read/Edit) → never touched
- Deny list → never modified
- Other settings.json fields (hooks, model, env, plugins) → never modified

**Test plan:**
- test_find_redundant: wildcard covers specific, no false positives across different commands
- test_find_flowstate_handled: detected but NOT in removals
- test_find_consolidations: narrowest wildcard, min_group threshold, root-only prefix
- test_apply_clean: atomic write, preserves deny, preserves other fields
- Integration: full CLI flow with tmp settings file

**Scope:**
- IN: `clean_cmd.py` module, `cli.py` subparser + `cmd_clean()`, status integration
- OUT: setup integration, suggest integration (deferred per design discussion)
- OUT: modifying deny list, hooks, or any non-allow field
