# #10 — Add --tier override flag to flowstate export

**Problem:** Exported profiles always use the user's current tier as `meta.recommendedTier`. A profile author running `flow` might want to publish a `cautious` profile for a security-focused audience.

**Current behavior:** `run_export()` reads tier from lockfile via `lockfile_mod.get_tier()`. No override mechanism.

**Expected behavior:** `flowstate export --tier cautious` sets `meta.recommendedTier` to `"cautious"` regardless of the user's actual tier. The flag only affects the metadata — it doesn't filter the exported rules.

**Edge cases:**
- Invalid tier name → error (reuse `VALID_TIERS` for validation)
- Tier mismatch warning: if user exports with `cautious` but has flow-level domains, warn that the profile content may exceed the recommended tier's typical scope

**Test plan:**
- Unit: `test_build_profile_tier_override` — verify meta.recommendedTier from parameter
- Integration: `test_run_export_tier_override` — verify --tier flows through
- Edge: `test_run_export_invalid_tier_error`

**Scope:**
- In: Add `--tier` arg to CLI with `choices=VALID_TIERS`, wire through to `build_profile`
- Out: Content filtering based on tier (that would be a separate feature)
