# #2 — Wire suggest_write_min_count for write vs read path thresholds

**Problem:** `tiers.py` defines `suggest_write_min_count` (10/5/3 per tier) for write path suggestions, separate from regular `suggest_min_count` (5/3/2). But `find_path_groups()` in `suggest.py` uses the same `min_count` for both read and write paths.

**Current behavior:** `find_path_groups()` in `src/flow_state/suggest.py` takes a single `min_count` parameter and applies it identically to all path suggestions. The caller passes the tier's `suggest_min_count`.

**Expected behavior:** Write path suggestions should use the higher `suggest_write_min_count` threshold. Write path suggestions should always get a warning label regardless of tier.

**Edge cases:**
- Path with reads above read threshold but writes below write threshold: suggest as read-only
- A path in both read and write audit entries: suggest separately with appropriate thresholds

**Test plan:**
- Unit test: write path below `suggest_write_min_count` but above `suggest_min_count` not suggested for write
- Unit test: write path above `suggest_write_min_count` suggested with warning flag
- Unit test: verify tier-specific write thresholds (cautious=10, balanced=5, flow=3)

**Scope:** `suggest.py` changes only. The `tiers.py` constants already exist.
