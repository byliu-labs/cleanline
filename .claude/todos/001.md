# #1 — Propagate flowstateTier in write_permission_config

**Problem:** When profiles are added/removed/updated, `lockfile.write_permission_config()` regenerates permission-config.json but does not include `flowstateTier`. Only `setup_cmd.generate_config()` sets this field. This means after any profile mutation, the tier metadata disappears from the config file.

**Current behavior:** `write_permission_config()` in `src/flow_state/lockfile.py` builds the output config from merged aliases/mappings/domains/fileAccess/resolvedCanonicals but never reads or writes `flowstateTier`. The tier is stored in `user_config["tier"]` in the lockfile.

**Expected behavior:** `write_permission_config()` should read the tier from `lockfile_data["user_config"]["tier"]` and include `"flowstateTier": tier` in the output permission-config.json. This keeps the config self-describing after any mutation.

**Edge cases:**
- Lockfile has no `user_config` or no `tier` key → default to `"balanced"`
- Existing permission-config.json already has `flowstateTier` from setup → should be overwritten with lockfile value (single source of truth)

**Test plan:**
- Unit test in `test_lockfile.py`: call `write_permission_config()` with lockfile_data containing `user_config.tier = "flow"`, verify output has `flowstateTier: "flow"`
- Unit test: missing tier in user_config → output has `flowstateTier: "balanced"`

**Scope:** Only `lockfile.write_permission_config()`. Do not change `generate_config()` or hook scripts.
